# Схема: как её порождать и как она читается

## Почему она порождается, а не рисуется

Схема из символов уезжает на один знак, и написавшему это не видно — ловит всегда только тот, кто
её читает, то есть тот самый человек, которому хотели помочь. Приложенный сборщик вычисляет каждую
позицию, а потом проверяет собственный вывод.

Схему не рисовать руками. И порождённую тоже не «подправлять» руками: править надо вход и собирать
заново.

## Как запустить сборщик

Сборщик едет вместе со скиллом, лежит в `scripts/render_map.py` внутри каталога скилла. Ему нужен
Python 3.9 или новее и больше ничего — ни пакетов, ни сети.

Записать зависимости в черновой файл, строка на поток:

```
1:              # никого не ждёт
2:
3:
4: 1            # ждёт поток 1
5: 1, 2
6: 1
7: 4
8: 4, 3
9: 7, 8, 6, 5
```

Затем собрать и проверить одним заходом:

```
python scripts/render_map.py streams.txt --check
```

Вывод:

```
   S1 ──┐
        │
   S2 ──┼─────► S5 ──────┬────────┬─┬─► S9
        │                │        │ │
   S3 ──┼──────────────┬─┼─► S8 ──┘ │
        │              │ │          │
        ├─────► S4 ────┤ │          │
        │              │ │          │
        └─────► S6 ────┼─┘          │
                       │            │
                       └───► S7 ────┘
```

Вставить это дословно в огороженный блок. `--check` печатает `check passed` в поток ошибок либо
перечисляет, что не так, и выходит с ненулевым кодом — упал, значит схема к владельцу не идёт.

### Ключи

| Ключ | Зачем |
|---|---|
| `--check` | Проверить собранную схему: каждый поток ровно один раз, колонки выровнены, лишних символов нет |
| `--prefix S` | Приставка к числовым обозначениям; `--prefix ""` даёт голые числа |
| `--format json` | Читать `{"streams": [{"id": "auth", "label": "auth", "depends_on": []}]}` вместо строчной записи |

Чтение из потока ввода тоже работает: `... | python scripts/render_map.py --check`.

### Какие ошибки он выдаёт

- `depends on unknown stream 'X'` — опечатка либо поток, который забыли объявить.
- `dependencies form a cycle between: ...` — неверна сама разбивка. См. раздел про кольца
  в `dependency-analysis.md`.
- `stream 'X' is declared twice` — две строки на один поток.

Это находки про твою разбивку, а не неполадки сборщика. Чинить разбивку.

## Как читается картинка

- **Колонка — это момент старта.** Всё, что в самой левой, можно открывать прямо сейчас. Следующая
  колонка открывается, когда влиты её зависимости, и так далее. В этом весь смысл: читатель считает
  колонку и знает, сколько вкладок открывать сегодня.
- **Каждый поток появляется ровно один раз.** Нарисованный дважды превращает одну картинку в две.
- **Пересечения — это нормально.** Позиция в колонке важнее, чем избегание пересечения; линия
  с дальней зависимостью честно пересекает те, что между.
- **На схеме только номера** (S1, S2). Названия живут в таблице.
- Ни заголовков, ни подписей колонок, ни пустых разделительных строк внутри картинки: подпись
  превращает одну схему в несколько.

## Если Python недоступен

Сказать об этом в ответе — не делать вид, что схема проверена. Дальше либо:

1. дать одну таблицу и отметить, что схема пропущена, потому что Python недоступен, либо
2. нарисовать руками и сказать, что нарисовано руками.

Для нарисованной руками правила такие: только символы псевдографики (`─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ ►`),
никаких дефисов и вертикальных черт; каждый поток один раз; подписи одной колонки начинаются на одной
и той же позиции; ответвление ставится на строке после подписи (`S1 ──┬──►`), а не под ней.
