# Настройка проекта

Скилл выдаёт задания, которые будет выполнять другая вкладка. Всё, что в этих заданиях зависит от
проекта — как вкладки изолируются, что здесь значит «сборка зелёная», какой разбор идёт перед
слиянием, — берётся из файла настройки, чтобы сам скилл оставался переносимым.

**Место:** `.parallel-streams.md` в корне репозитория.
**Необязателен:** без него действуют значения по умолчанию, и итоговый абзац говорит об этом один раз.

‼️ **Заголовки разделов скилл ищет по-английски** — `## Isolation`, `## Tests` и так далее. Их не
переводить: это адреса, по которым читают файл. Переводится содержимое разделов, и пишется оно на
языке проекта.

## Поля

| Раздел | Что задаёт | Значение по умолчанию |
|---|---|---|
| `## Isolation` | Как вкладка получает рабочее место, которое никто снаружи не сдвинет | отдельное рабочее дерево на поток |
| `## Stream size` | Размер, за который поток не должен выходить | один читаемый запрос на слияние |
| `## Tests` | Команда, доказывающая, что поток работает | штатная команда проверок проекта |
| `## Gates` | Линтеры, типы, форматирование и где гоняется тяжёлое | штатные проверки проекта |
| `## Review` | Разбор перед запросом на слияние, его глубины и можно ли потоку ответить «не нужен» | разбор перед слиянием; «не нужен» — только для изменения, которое не может изменить поведение |
| `## Security review` | Дополнительный проход и что его вызывает | деньги, права доступа, ключи, границы с сетью |
| `## Delegation` | Что вкладка отдаёт субагенту и какой уровень модели на какой род работы | разведка и выполнение каждой задачи — субагентам, выполненное проверяет другой; дешёвый уровень на разведку и механику, уровень вкладки на новую логику, разбор — не ниже уровня вкладки |
| `## Escalation` | Как в этом проекте называют более глубокий режим и как его просят | описывается в задании общими словами |
| `## Merge` | Кто вливает, слияние сжатием или перебазированием, должны ли проверки быть зелёными | вкладка вливает свой запрос сама, когда проверки прошли |
| `## Conventions` | Именование веток, язык и приставки сообщений коммитов | существующий стиль репозитория |
| `## Settled decisions` | Путь к реестру уже закрытых развилок | нет |
| `## Persistent rules` | Файл, который загружает каждая вкладка проекта на старте (`CLAUDE.md`, `AGENTS.md`, …) и который обязан нести правила, действующие и тогда, когда задача пришла не от этого скилла | отсутствует — скилл говорит об этом один раз в итоге и предлагает блок из `references/persistent-rules.md` |
| `## Brief language` | Язык, на котором пишутся задания | язык, на котором говорит владелец |
| `## Coordination` | Команды, которыми работающие вкладки достают друг друга, — копируются дословно в блоки 4 и 9 каждого задания | отсутствует — скилл не говорит про согласование ничего |
| `## Plans` | Папка, где лежат планы волн, в обратных кавычках | отсутствует — сторож-подсказка канала не подключается |

Незнакомые разделы игнорируются, поэтому настройка может нести и заметки для людей.

## Пример

```markdown
# Настройка parallel-streams

## Isolation
Отдельное рабочее дерево на поток, ветка от свежего origin/main. Вкладки идут по одной папке
проекта — без своего дерева они затирают друг другу активную ветку.

## Stream size
Один запрос на слияние меньше 400 строк изменений либо короткая цепочка небольших в одной ветке.

## Tests
`npm test` по тронутому пакету. Сквозные проверки — только когда поток меняет адрес обращения.

## Gates
`npm run lint && npm run typecheck` локально. Полная матрица гоняется в сборочной службе — на машине
разработки её не запускать.

## Review
Прогнать штатную команду разбора по изменениям потока до запроса на слияние. Глубина по умолчанию —
глубокая. Механическая работа по существующему образцу — обычная. Поток, чьё изменение не может
изменить поведение (документация, переводы строк, номер версии), может ответить «не нужен» с
причиной; если в проекте не пропускают никогда — написать здесь «проверку несёт каждый поток».

## Security review
Дополнительно обязателен для: денег, входа, прав доступа, обращения с ключами, всего, что открыто
в сеть.

## Delegation
Чтение и разведка уходят субагенту, а не в собственный контекст вкладки. Так же и выполнение каждой
задачи: один субагент пишет, другой сверяет с заданием, вкладка принимает. Уровни: разведка —
быстрая дешёвая модель; механическая задача, рядом с которой лежит готовый образец, — тоже быстрая
дешёвая; задача с новой логикой — та, на которой идёт вкладка; разбор и аудит — не слабее уровня
вкладки.

## Escalation
Здесь это называют «ультракод». Вкладка просит его отдельной строкой и ждёт ответа: помеченный шаг
без него не начинает.

## Merge
Вкладка открывает и вливает свой запрос на слияние сама, когда проверки зелёные. Слияние сжатием.
Напрямую в основную ветку не коммитить.

## Conventions
Ветка: `feat/<тема>` или `fix/<тема>`. Коммиты: повелительное наклонение, конвенциональная приставка,
по-русски.

## Settled decisions
`docs/decisions/INDEX.md` — сверяться перед архитектурным предложением; отвергнутые варианты записаны
там вместе с причинами.

## Persistent rules
`CLAUDE.md` в корне репозитория. Он несёт то, что обязано действовать при любом способе прихода
задачи: кто владелец и чего он не читает, что отчёт субагента до него не доходит нетронутым, и в
какие несколько моментов вкладка вообще пишет текстом. Эта настройка повторяет те же правила для
заданий; два файла держатся одинаковыми, и при расхождении верен `CLAUDE.md`.

## Brief language
Русский.
```

## Разделы Coordination и Plans

Эти два раздела приходят от канала согласования — необязательной механики в `coordination/`. Её
установщик пишет оба сам, уже заполненными, поэтому они — единственная часть настройки, которую не
стоит писать руками: команды из `## Coordination` копируются в каждое задание дословно, а команда,
разошедшаяся с инструментом, хуже, чем отсутствие команды.

Оставить оба раздела за бортом — поддержанный способ работы: скилл тогда ведёт себя ровно так, как
вёл до появления канала. Установка и удаление — `coordination/README.md`.

## Почему одной настройки мало

Настройка доходит до вкладки через задание, а задание доходит ровно до тех вкладок, которые нарезал
этот скилл. Задача, набранная руками прямо в чате, план, написанный кем-то самостоятельно, вкладка,
открытая завтра ради одной мелкой правки, — ни одна из них настройку не загружает. Правила, которые
обязаны пережить этот разрыв, должны лежать ещё и в постоянном файле правил, а план несёт их третий
раз — для тех вкладок, которые открывают только план. Что где лежит, какой блок вставлять и какое
падение всё это породило: `persistent-rules.md`.

## Заметки

- Настройку стоит написать один раз на репозиторий. Это разница между заданиями, которые читаются как
  общий список для галочки, и заданиями, которые читаются как написанные коллегой по проекту.
- Держать её короткой. Всё, что здесь есть, повторяется в каждом задании; раздутая настройка раздувает
  каждый поток.
- Если репозиторий уже описывает эти вещи в другом документе (руководство участника, `CLAUDE.md`,
  файл правил для агентов), настройка может сослаться на него вместо пересказа.
